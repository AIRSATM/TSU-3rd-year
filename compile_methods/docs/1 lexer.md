# Лексический анализатор (C#)

Файлы: [src/MiniLang/Lexing/Token.cs](../src/MiniLang/Lexing/Token.cs),
[src/MiniLang/Lexing/Lexer.cs](../src/MiniLang/Lexing/Lexer.cs).

Класс `Lexer` — табличный детерминированный конечный автомат (ДКА).
Он одинаково ведёт себя на любых входах, потому что переходы выбираются
по двум координатам:

```
(текущее состояние, класс символа) → (следующее состояние, действие)
```

## 1. Состояния и классы символов

```
LexState         CharClass
─────────────    ─────────────
Start            Letter      (a..z A..Z _)
InIdent          Digit       (0..9)
InInt            Dot         '.'
InReal           Op          ( + - * / < > = ! )
InOpStart        Lparen      '('   ...
InColon          Rparen      ')'
InComment        Lbrack      '['
                 Rbrack      ']'
                 Semi        ';'
                 Comma       ','
                 Colon       ':'
                 Slash       '/'
                 Eq          '='
                 Lt          '<'
                 Gt          '>'
                 Ws          (пробел, табы, перевод строки)
                 Eof
                 Other       (всё прочее → ошибка)
```

`Classify(int)` отображает реальный символ в `CharClass`,
`TransitionTable[state, class]` хранит ячейку `Cell { NextState, Action }`,
где `Action` — одно из:

| Действие  | Что значит                                                          |
| --------- | ------------------------------------------------------------------- |
| `Accum`   | Добавить текущий символ в накопитель и сдвинуться                   |
| `Skip`    | Пропустить символ, накопитель не трогать                            |
| `Emit`    | Выдать токен, символ не потреблять                                  |
| `EmitC`   | Выдать токен и потребить текущий символ                             |
| `Error`   | Лексическая ошибка                                                  |

Заполнение таблицы выполняется один раз в `BuildTransitionTable()`:
для каждого состояния сначала проставляется `Err` по всем классам,
затем — переходы по списочкам «всё, кроме Letter» и т. п.

## 2. Что распознаётся

* **Идентификаторы**: `[A-Za-z_][A-Za-z_0-9]*`.
* **Целые числа**: цепочка цифр, парсятся в `long` (поле `Token.Value: double`).
* **Вещественные числа**: `цифры '.' цифры` (точка обязательно с дробной частью).
* **Ключевые слова** распознаются после идентификатора через словарь
  `Keywords` — поэтому `ifx` остаётся `IDENT`.
* **Операторы**: `+ - * / := < > <= >= = <>`. Двухсимвольные собираются
  через промежуточные состояния `InColon`, `InOpStart` (`<` / `>` / `=`).
* **Пунктуация**: `( ) [ ] ; ,`.
* **Комментарии**: от `//` до конца строки. Реализованы через `Slash` →
  второй `/` → состояние `InComment`, в котором всё, кроме перевода
  строки, пропускается.
* **Координаты**: `Advance()` инкрементирует `_col`, на `\n` сбрасывает
  колонку и увеличивает `_line`. Координаты привязываются к токену
  в момент его старта.

## 3. Ошибки

`LexException(line, col, message)` форматирует:

```
Лексическая ошибка [строка L, символ C]: <причина>
```

Пример причин:

* «недопустимый символ '@'»,
* «ожидалась цифра после '.'» (для `12.`),
* «незакрытый оператор»,
* ошибка `double.TryParse` для синтаксически валидного, но не
  поддерживаемого числа.

## 4. Использование из кода

```csharp
using MiniLang.Lexing;

var tokens = Lexer.Tokenize("x := 1 + 2");
foreach (var t in tokens)
    Console.WriteLine($"{t.Type.Display()} '{t.Lexeme}' @ {t.Line}:{t.Col}");
```

`Token` — `readonly record struct` со свойствами:
`Type`, `Lexeme`, `Value` (только для `INT` / `REAL`), `Line`, `Col`.

Из CLI этот этап вызывается флагом `--tokens`:

```bash
dotnet run --project src/MiniLang.Cli -c Release -- --tokens examples/01_formulas.ml
```
