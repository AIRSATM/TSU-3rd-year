# Обратная польская запись (C#)

ОПС (RPN) — линейный массив `RpnItem`, который парсер порождает по ходу
разбора и который потом исполняет интерпретатор.
Файлы: [src/MiniLang/Parsing/Rpn.cs](../src/MiniLang/Parsing/Rpn.cs),
[src/MiniLang/Parsing/Parser.cs](../src/MiniLang/Parsing/Parser.cs),
[src/MiniLang/Interpreting/Interpreter.cs](../src/MiniLang/Interpreting/Interpreter.cs).

## 1. Элемент ОПС

```csharp
public sealed class RpnItem
{
    public RpnKind Kind;   // Num | Var | Op | Lbl
    public double  Num;    // для Num
    public string  Name;   // для Var
    public OpCode  Op;     // для Op
    public int     Addr;   // для Lbl (мутируется при back-patching)
    public int     Line, Col;
}
```

* `Num` — числовая константа,
* `Var` — имя переменной (lvalue),
* `Op`  — операция (см. ниже),
* `Lbl` — метка перехода: целочисленный адрес внутри массива ОПС.

`Addr` сделан изменяемым полем (поэтому `RpnItem` — `class`,
не `readonly struct`): при компиляции `if`/`while` метку
приходится **подставлять задним числом** (back-patching).

## 2. Операции

| `OpCode`               | Отображение | Семантика                                        |
| ---------------------- | ----------- | ------------------------------------------------ |
| `Add Sub Mul Div`      | `+ - * /`   | арифметика, `Div` бросает ошибку при делении на 0 |
| `Neg`                  | `@-`        | унарный минус                                    |
| `Lt Gt Le Ge Eq Ne`    | `< > <= >= = <>` | сравнения, возвращают `1.0` / `0.0`         |
| `Assign`               | `:=`        | присваивание; снимает `value`, потом `lvalue`    |
| `Index`                | `[]`        | из `(lval, num)` строит адрес элемента массива   |
| `Rval`                 | `RVAL`      | разыменование: lvalue → число                    |
| `Decl`                 | `DECL`      | объявление массива (`array a[n]`)                |
| `Read Write`           | `READ WRITE`| ввод/вывод                                       |
| `Jmp`                  | `JMP`       | безусловный переход (адрес на стеке)             |
| `Jz`                   | `JZ`        | переход если 0 (адрес и значение на стеке)       |
| `Halt`                 | `HALT`      | конец программы                                  |

## 3. Семантические действия и генерация ОПС

Парсер порождает ОПС не по AST, а сразу по ходу разбора —
семантические действия встроены в правые части правил
(см. [grammar.md](grammar.md)).

| Действие         | Что порождает в ОПС                                          |
| ---------------- | ------------------------------------------------------------ |
| `PushNum`        | `Num(значение последнего INT/REAL)`                          |
| `PushVar`        | `Var(имя последнего IDENT)`                                  |
| `OpAdd … OpDiv`  | соответствующий `Op`                                         |
| `OpNeg`          | `Op(Neg)`                                                    |
| `OpRel`          | `Op(<…>)` — выбирается по типу запомненного RelOp-токена     |
| `OpIndex`        | `Op(Index)`                                                  |
| `OpRval`         | `Op(Rval)`                                                   |
| `OpAssign`       | `Op(Assign)`                                                 |
| `OpDecl`         | `Op(Decl)`                                                   |
| `OpRead`         | `Op(Read)`                                                   |
| `OpWrite`        | `Op(Write)`                                                  |
| `IfAfterCond`    | `Lbl(?) Op(Jz)` — адрес пока неизвестен, кладём `-1` в стек меток |
| `IfAfterThen`    | `Lbl(?) Op(Jmp)`, потом **корректирует** ранее отложенный `Lbl` на текущую позицию |
| `IfNoElse`       | **корректирует** `Lbl` после `Jz` на текущую позицию         |
| `IfEnd`          | **корректирует** `Lbl` после `Jmp` на текущую позицию         |
| `WhileBegin`     | запоминает текущую позицию (начало цикла)                    |
| `WhileAfterCond` | `Lbl(?) Op(Jz)`                                              |
| `WhileEnd`       | `Lbl(begin) Op(Jmp)` плюс правка метки выхода                |

«Корректирует задним числом» означает, что мы редактируем поле `Addr`
у элемента `Lbl`, который ранее добавили со значением `-1`.

## 4. Примеры

### 4.1. Простое выражение

Исходник:

```minilang
x := 2 + 3 * 4
```

ОПС:

```
 0: x         // PushVar
 1: 2         // PushNum
 2: 3
 3: 4
 4: *         // OpMul
 5: +         // OpAdd
 6: :=        // OpAssign
 7: HALT
```

### 4.2. `if … then … else … end`

Исходник:

```minilang
if x > 0 then write(1) else write(2) end
```

Что порождает парсер по шагам:

| Шаг             | Действие              | Элементы ОПС, добавленные на этом шаге |
| --------------- | --------------------- | -------------------------------------- |
| разбор `Cond`   | `PushVar` `PushNum` `OpRel` | `x  0  >`                          |
| `IfAfterCond`   | `Lbl(?) Jz`           | `L(?1)  JZ`                            |
| ветка THEN      | `write(1)`            | `1  WRITE`                             |
| `IfAfterThen`   | `Lbl(?) Jmp` + правка `?1` | `L(?2)  JMP`; `?1` ← текущий адрес |
| ветка ELSE      | `write(2)`            | `2  WRITE`                             |
| `IfEnd`         | правка `?2`           | `?2` ← текущий адрес                   |

### 4.3. `while`

```minilang
while i < n do
    s := s + i;
    i := i + 1
end
```

* Перед `Cond` `WhileBegin` запоминает текущий адрес `begin`.
* `WhileAfterCond` после условия выдаёт `Lbl(?) Jz` и кладёт метку выхода
  в стек.
* `WhileEnd` после тела выдаёт `Lbl(begin) Jmp` (возврат к началу) и
  подставляет адрес выхода — он равен текущему адресу,
  то есть позиции **сразу после** `Jmp`.

## 5. Выполнение

`Interpreter.Run(rpn, stdin, stdout)` обходит массив по индексу `ip`
и поддерживает стек значений `RtValue` трёх видов:

* `Num`  — число,
* `LVal` — имя переменной,
* `LAddr` — пара (имя массива, индекс).

* Арифметика/сравнения снимают два операнда, через `ResolveNum`
  превращают `LVal`/`LAddr` в число, и кладут результат.
* `Index` снимает `(LVal, Num)` → кладёт `LAddr`.
* `Rval` явно превращает верхний `LVal`/`LAddr` в `Num`.
* `Assign` снимает `(target, value)` и пишет в переменную/элемент.
* `Decl` снимает `(name, size)`, аллоцирует `double[size]` в словаре массивов.
* `Read` снимает цель, читает число из stdin через `NumberReader`.
* `Write` снимает значение и печатает (`FormatNumber` показывает целое без
  десятичной точки, если значение целое и в диапазоне `long`).
* `Jmp`/`Jz` снимают адрес (а для `Jz` — ещё и условие) и обновляют `ip`.
* `Halt` завершает выполнение.

Все рантайм-ошибки (деление на ноль, индекс вне границ, использование
неинициализированной переменной, неверный размер массива и т. п.)
кидаются как `RuntimeException` с теми же координатами `Line`/`Col`,
что у соответствующего `RpnItem`.
